# Contributing

Use a branch and a focused pull request. Reference backlog IDs and describe what changed, why, validation and remaining limitations. Greg reviews business direction and any expanded scope.

Documentation acceptance: relative links resolve; prompts include shared policy; estimates are labeled; no customer data or secrets; tables and code fences render correctly; backlog statuses reflect actual evidence. No application tests are required for prose-only edits. Inspect Markdown changes and run a local relative-link check.

Future code work needs a separate implementation scope, coding standards, meaningful acceptance tests and isolated fixtures. Production release, outreach and spending remain outside the current scope.
