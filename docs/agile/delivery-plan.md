# Agile delivery plan

## Product goal

Validate a repeatable paid workflow service while reducing Greg's routine preparation work with AI. Start with one buyer segment and one bounded offer. Runtime sophistication is not a success metric.

## Roles and cadence

Greg is product owner and final commercial decision-maker. Repository contributors maintain plans and reviewable artifacts. Proposed agent role owners are documented, not active employees or systems.

Use one-week sprints measured from actual start, not invented calendar commitments. Plan at sprint start; use a short asynchronous progress update when work occurs; review evidence and retrospect at sprint end. Track Todo, In progress, Review, Blocked and Done. Limit work in progress to one substantial item per contributor. Estimates are relative effort, not commitments.

## Definition of ready

A story has a buyer or operator outcome, owner, dependencies, bounded scope, acceptance criteria and appropriate data permissions. Stories requiring external execution remain blocked until explicitly authorized.

## Definition of done

Deliverable exists, acceptance evidence is recorded, references resolve, independent review is completed when required and open limitations are clear. Merging documents does not activate agents or validate demand. A sprint with only a plan must not claim operational capability.

## Roadmap

| Sprint | Outcome | Entry gate | Exit evidence |
|---|---|---|---|
| 1 | Planning foundation | Repository access | Linked plans, instructions, backlog and review |
| 2 | Fictional service rehearsal documents | Offer and buyer decision | Sample assessment, proposal and critique; no live runtime |
| 3 | Implementation design | Explicit design scope | Current tool inventory, platform decision, cost and access design |
| 4 | Controlled internal implementation | Explicit implementation authorization | Enforced controls and measured evaluation results |
| 5 | One paid pilot | Customer scope and access approval | Trusted payment, acceptance and actual labor records |

Only Sprint 1 documentation is being prepared now. Later sprints are proposals, not authorization to implement. No paid tools or cloud services are required for planning.
